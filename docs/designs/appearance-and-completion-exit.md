## 1. 本轮边界

只做主窗口透明度、悬浮条背景透明度、悬浮条精修、下载完成后正常退出。复用现有 ConfigManager、SettingsDialog、FloatBar、完成动作和任务活动保护。

不新增依赖、数据库迁移、浏览器/Native 协议、任务状态、毛玻璃/系统材质或动画框架；不改下载引擎、限速/续传、平台适配、批量选择及自动分目录逻辑。不顺带做定时、链接更新、分页、侧栏滚动或跨任务去重。

主界面字体、13 逻辑像素侧栏、240px 侧栏宽度、全局 DPI、主窗口布局保持。原 `dist/data`、`dist/temp`、根运行数据和下载文件不能被测试覆盖或清理。不提交、推送、发 Release、改正式版本号或写/同步长期记忆。

## 2. 设置页与透明度

### 2.1 布局

设置保持当前 560×600 逻辑尺寸，增加“外观”页，不把更多控件硬塞进旧“其他”页：

```text
下载 | 外观 | 其他

外观：
主题                 深色 / 浅色 / 跟随系统
主窗口不透明度       [60 ────────── 100]  100%
                     100% 为完全不透明；主窗口文字会一起变淡。
                     设置与确认窗口保持不透明。

桌面悬浮条           [ ] 显示可拖动的速度悬浮条
悬浮条样式           完整 / 迷你
悬浮条背景不透明度   [30 ────────── 100]  100%
                     只调整背景，文字和进度保持清晰。

其他 / 下载完成后：
[ ] 打开文件
[ ] 打开所在文件夹
全部完成后           不操作 / 退出下载器 / 关闭电脑
                     退出前 10 秒、关机前 60 秒均可取消。
                     本轮有失败或未完成任务时不自动退出。
```

原下载页和剪贴板设置保持；主题、悬浮条开关和样式从“其他”移到“外观”，不复制两套入口。说明文字须受宽度约束，滑块和百分比对齐；100/150/200% 缩放下按钮不被裁切。若保持现尺寸确实放不下，优先压缩无效留白/调整标签排版，不擅自放大主窗口或改字号。

### 2.2 配置契约

| 字段 | 值 | 默认/兼容 |
|---|---|---|
| `ui_window_opacity` | 整数百分比 60–100 | 缺失为 100 |
| `ui_float_bar_opacity` | 整数百分比 30–100 | 缺失为 100 |
| `after_download.exit_app` | bool | 缺失为 false |
| `after_download.shutdown` | 原 bool | 老配置为 true 时继续关机，不静默改成退出 |

- 透明度用“**不透明度**”统一命名：100% 完全不透明。不要一处存 0–1、另一处按 0–100 解释。
- 有限数字四舍五入为整数并夹取范围；空值、布尔、非数字、NaN、Infinity、溢出安全回退 100，不让窗口消失。
- `after_download` 继续保留 open_file、open_folder、shutdown，并新增 exit_app。读写都保证 exit_app/shutdown 互斥；损坏配置同时为 true 时优先低风险的退出并置 shutdown=false。
- 旧 after_download 缺键不异常；非字典损坏值按关闭动作处理。不要借机重写全部配置系统。

### 2.3 预览与持久化

1. 滑动时实时预览且显示整数百分比；预览只影响窗口，不修改共享配置对象、配置文件、任务或数据库。
2. 保存成功后才持久化并同步主窗口/现有悬浮条，重启恢复。取消、右上角关闭、销毁设置框应恢复打开前的透明度。
3. 保存失败：配置内存和运行时恢复旧值，文件保留原状，留在设置页显示既有错误反馈。控件可保留输入供重试，但不能把预览误认为保存成功。
4. “恢复默认”保持现有确认及立即保存语义；成功后两者均 100%，并更新本次取消的回退基线。随后再预览再取消，回到默认而非重置前的旧值。重置失败不得应用新默认。
5. 悬浮条关闭时可先设数值，但不为预览擅自开启或改开关；保存启用后首次创建即使用保存值。主题、完整/迷你、隐藏/重显后数值不丢失。
6. 设置、删除、详情、完成动作等独立 Toplevel 不跟随主窗口变淡；拖到低透明度仍能清楚恢复默认。不新增鼠标穿透、隐藏窗口或悬停变不透明功能。
7. 保持“保存成功不弹窗、主窗口状态栏提示”的现行约定。退出销毁过程中预览回退应安全跳过已销毁窗口，不留 Tk 回调异常。

## 3. 悬浮条渲染与精修

### 3.1 已确认的技术问题

当前 `LayeredSurface.push` 用 `image.convert('RGBa').convert('RGBA')`，第二次转换会撤销预乘，却仍以 `AC_SRC_ALPHA` 交给要求预乘 BGRA 的 Windows。

最小实验：RGBA (200,100,50,128) 经原路径变成 BGRA [49,99,199,128]；正确预乘应为 **[25,50,100,128]**。本机 py310_env 的 Pillow 已确认支持 `convert('RGBa').tobytes('raw', 'BGRa')`。可抽出纯字节转换函数并由生产 push 真正调用，不能只修测试里的转换。

该问题在纯像素合成对照中呈现浅色卡片深背景边缘毛刺，但尚未进行新功能实际 EXE 验收，也不能把全部观感问题都归因于这一处。

### 3.2 固定渲染约束

- 保留 Pillow **4 倍超采样 + LANCZOS + UpdateLayeredWindow**。不退回 Canvas 折线或色键透明，不仅靠从 4 倍提高到 8 倍掩盖问题。
- 主窗口用 Tk `-alpha` 调整体不透明度；悬浮条通过 RGBA 绘制调整背景，**不能调用其 Tk -alpha / SetLayeredWindowAttributes**，否则可能使后续 UpdateLayeredWindow 失败。
- 主卡面、边框和阴影按背景百分比绘制；文字、状态点、已填充进度、曲线主线保留原有前景可读性，不对整张成图再统一乘 alpha。
- 预乘字节每个颜色通道应 ≤ alpha；alpha=0 时颜色为零。半透明边缘在浅、深、彩色背景上不出现键色边或发白轮廓。
- 生产 GDI 路径须真实成功推帧；只有 render_bar 输出好看不足以验收。触及位图句柄时正确回选/释放，不新增句柄泄漏，不把失败返回值吞掉并声称已生效。

### 3.3 视觉方向

定位为“轻量、克制的桌面工具”，沿用绿主色和深浅主题，保留完整 **280×118**、迷你 **158×34** 的逻辑体积，不扩大窗口或引入花哨渐变。

1. 单层细边替代双圈硬亮边，圆角一致，悬停仅轻微提升边框，不用粗亮框。
2. 保留现有字体及字号：速度为主视觉，百分比次之，文件名/剩余时间弱一层；只精修字重、基线和留白，避免挤压/截断速度数值。
3. 进度条更简洁，去掉明显的上下硬分层；曲线主线、面积和端点收敛，不让曲线抢过速度数字。空闲仍不画假绿色下载线。
4. 轻柔阴影允许，但须限制在现有像素画布内，避免裁切成黑线；四角外部仍真正透明，不能为阴影放大窗口、破坏贴边或引入大块点击拦截。
5. 可在精修范围调整小量内边距/线宽，不改变窗口尺寸、全局缩放或其他区域字号。最终提供完整/迷你、深/浅、至少低透明度和 100% 的对照图。

必须保留拖动贴边、位置记忆、双击显示主窗，以及原右键菜单：显示主窗口、分隔、迷你模式、分隔、暂停全部、继续全部、分隔、设置…、隐藏悬浮条、分隔、退出程序。菜单原生 Tk 字号仍是原公式的**负像素值**，不得改成正磅值。

## 4. 完成后自动退出

### 4.1 动作与触发

队列动作“不操作 / 退出下载器 / 关闭电脑”互斥，默认不操作；打开文件/所在文件夹独立保留并按原顺序执行。关机沿用 60 秒确认，不执行真实关机来测试。新增退出是**正常退出整个下载器**，不是最小化到托盘，不受右上角关闭时“最小化”的选择影响。

只有本轮全部任务 `completed`（含正常校验成功）才允许退出；速度为零、百分比为 100、verifying、verify_failed、最后一个回调恰好是 completed 都不是充分条件。

### 4.2 “本轮”定义

轮次仅为内存状态，不新增表/任务状态或将轮次写进配置：

| 情况 | 行为 |
|---|---|
| 冷启动只存在历史完成/失败/暂停记录 | 不建立成功轮次，不自动退出 |
| 保存开启退出时已有 pending/downloading/verifying | 将当前活跃任务纳入本轮 |
| 新任务实际等待/启动/校验，或旧任务被恢复/重试 | 纳入当前未结束轮次；若上一轮已结束，则开启新轮次 |
| “稍后下载”直接 paused、从未参与本轮 | 不凭添加记录本身纳入成功轮次 |
| 已参与本轮的任务暂停/失败/校验失败/取消/被删 | 不能漏掉；队列空闲时本轮不退出 |
| 暂停任务在本轮空闲收尾前恢复并最终成功 | 仍属于本轮，可在全部成功后退出 |
| 本轮空闲结束但未全成功，后来又实际启动任务 | 开启新轮次，旧轮失败/暂停不永久阻挡 |
| 退出倒计时被取消或失效 | 本轮已经消费，不因重复完成回调再弹；新实际任务才开启新轮 |

使用实际数据库状态复核终态；轮次追踪不能只看 UI 当前卡片或只记最后完成的任务。处理回调时可能已有更新的数据库终态，应保留对本轮参与者的记忆，同时阻止迟到旧事件为同一轮重新开倒计时。内部网络重试不是新的用户轮次。

### 4.3 空闲与竞态保护

满足以下条件后再弹 **10 秒、可取消**的退出确认：

- 本轮非空且全成功；无下载、等待、校验、后台探测、在途添加或批量操作。
- UI 状态事件已收敛，既有设置/删除等模态窗口结束；不要在已有 modal 上抢 grab 或叠完成弹窗。
- 不因开启设置或应用启动本身触发退出；仅修改透明度且完成动作未变时，不重置正在下载的轮次。

复用 `TaskManager.get_activity_state()` 的活动代数及 `_has_active_tasks()` 保护，不另造调度器。窗口弹出时固定本轮 task IDs、活动代数及完成动作版本：

1. 倒计时中任何新增/启动/重试使旧确认失效，即使新任务极快完成、检查时已经没活动任务也一样。
2. 完成动作保存发生实际变化（含关掉又开启）使旧确认失效；只判断当前开关为 true 不足够。取消/关闭后不反复提示。
3. 点击“立即退出”和倒计时到零共用同一个最终有效性检查，不可旁路；查库暂时失败应延后/取消，不能按没有任务处理。
4. 先确认无活动再提交正常退出，必须覆盖关闭入口间隙；复用已有 shutdown_started、探测收敛和调度保护，避免最后检查后仍接受新任务并悄悄中止它。
5. worker 不操作 Tk；不要在 Tk 主线程无界等网络、不要从线程池里 join 自己、不要持任务锁跑模态事件循环。定时器在取消/退出时撤销，主窗销毁不留异常。

可复用/小范围抽取现有关机倒计时 UI；不必为两种动作引入通用插件/策略框架。最终调用 `_exit_app`，清理 BrowserBridge、托盘、悬浮条与任务管理器，保留断点及下载文件，不用 os._exit、taskkill 或 terminate 逃避清理。
