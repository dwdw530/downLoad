## 1. 目标、范围与不变量

支持从下载器现有添加入口提交的、成功响应为 `200` 且没有 `Content-Length` 的有限 HTTP/HTTPS 普通文件。复用现有非 Range 单线程流程，流式写盘；不增加独立下载路径、第三方依赖、配置项或数据库列。多行添加和“稍后下载”通过同一引擎规则自然支持，不改变各自编排。

`200 + Content-Length: 0` 是否一并支持，由用户按第 3 节决定。两案都允许“没有 Length、读取后实际为 0 字节”的正常响应；B 限制显式零长度响应，不承诺拒绝所有最终为空的流。

必须保持的边界：

1. **插件与桥接零修改**：`chrome-extension/`、Native Messaging 消息与版本、BrowserBridge 相关源码及入口、扩展版本 `0.6.2` 全部不动。
2. **浏览器入口行为零扩展**：右键普通链接原先拒绝的未知大小、零字节链接仍拒绝。不能只保证桥接源码无差异，却让回执、任务创建或后续出队行为变化。
3. **既有正大小行为不变**：不支持 Range 的有大小文件、Range 单线程、多线程、断点身份核对、限速、空间检查、重试分类和视频下载均保持原有分支。
4. **文件与数据保护不变**：复用文件名校验、事务内路径预留、启动前重查、非覆盖发布；不搬移、清空或升级用户配置、数据库和断点。
5. **UI 零修改**：复用现有进度、状态和回调，不新增动画、文案控件或设置。零字节显示边界见第 9 节。
6. **原设计阶段边界**：当时只交付本文，不写实现、不执行测试或打包。后续用户已确认实现、独立回归和 v0.10.0 提交 / 打包 / 发布，按新增授权执行；插件与运行数据保护约束继续有效。

## 3. 已选方案 A：显式零长度响应

| 方案 | 200 且缺少 Length | 200 + Length: 0 | 利益 | 代价 |
|---|---|---|---|---|
| **A：两者均放行，推荐** | 下载至正常 EOF，实际可为空 | 仍发正式 GET，创建实际空文件并校验 | 合法空对象可下载；无长度和显式空对象体验一致 | 非预期成功空响应也可能成为空文件；UI 原有零大小占位保留 |
| **B：仅缺少 Length 放行** | 下载至正常 EOF，实际仍可为空 | 保持拒绝和 `no_length` 口径 | 保留显式零长度的旧拒绝行为 | 合法空文件仍下不了；仅改变长度头就会得到不同结果，且不能排除无 Length 的空流 |

**推荐 A**：符合本次“未知大小 / 零字节下载”的完整目标，文件、哈希、状态与历史保持真实。使用 HTTP 正常结束及可选预期哈希约束结果，不把空文件一概视为错误。

决策只对自身无浏览器上下文的普通文件生效。**两案均保持浏览器右键未知大小 / 空文件拒绝。**

若选择 B，添加探测、启动重探测及新模式正式 GET 遇到显式 `Length: 0` 都拒绝；不能添加时拒绝、正式 GET 却接收。无 Length 的正常空流仍允许，不擅自扩大为“实际字节必须大于 0”。

不增加用户开关；已按方案 A 固定实施，不增加方案 B 才需要的 accept_empty_response 参数。

## 4. 探测判定与入口隔离

### 4.1 判定顺序与兼容返回值

保留 `check_url_support_range(url, request_context=None, metadata=None) -> (bool, int)`，继续一次流式 GET 探测并关闭响应，不把探测体当最终文件。请求头、超时、代理、重定向、文件名优先级均保持原样。

在现有 `metadata` 中增加内部字段，不进入 Native 消息或数据库：

- `probe_ok`：每次调用先重置为 False，仅通过状态、编码和长度 / Range 检查后设 True。
- `length_kind`：成功时取 `known`、`unknown`、`empty`；失败时清空，不能保留上次成功值。
- 现有 `reason/status/error/etag/last_modified/filename/final_url` 保留。失败继续写原原因，成功清除本次失败标记。

调用方必须联合核对成功标记、长度类别和入口资格，不能把任意 `(False, 0)` 当成功，也不能仅以 `reason is None` 判成功。没有传 metadata 的旧调用仍得到原二元组；两个生产调用点都已传 metadata，继续在引擎内消费新增分类。

| 最终探测响应 | 下载器自身普通文件 | 浏览器上下文任务 | 返回及约束 |
|---|---|---|---|
| 206 严格匹配 `Content-Range: bytes 0-0/N`，且 N>0 | 原样接受 | 原样接受 | `(True, N)`；原 Range、验证器和线程规则不变 |
| 200 可按现有规则解析出 Length>0 | 原样接受 | 原样接受 | `(False, N)`；非 Range 有大小链路不变 |
| 200 **完全缺少** Length，编码 identity 或未设置 | 新增接受 | **保持拒绝** | 自身返回 `(False, 0)`，`probe_ok=True`、`length_kind=unknown`；浏览器保留 `no_length` |
| 200 明确 Length=0 | A 接受，B 拒绝 | **保持拒绝** | A 的自身入口标记 `probe_ok=True`、`length_kind=empty`；其余保持 `no_length` |
| Length 为空字符串、负数、非法或冲突 | 拒绝 | 拒绝 | 解析不了不等于“缺少头”，不能进入新成功类别 |
| 非 identity 的 Content-Encoding，含 gzip/br/deflate | 拒绝 | 拒绝 | 沿用 `encoding_not_supported`，不自动解压后按范围保存 |
| 401/403 且为 HTML 登录页 | 拒绝 | 拒绝 | 沿用 `html_page` 和原 HTTP 状态提示 |
| 其他 4xx/5xx、超时、DNS、连接错误 | 拒绝 | 拒绝 | 原分类和错误槽不变；429/5xx 在添加探测阶段仍不创建任务 |
| 非法 / 缺失的 206 Content-Range、其他状态 | 拒绝 | 拒绝 | 原协议或其他失败，不降格为未知大小 |

补充边界：

- Transfer-Encoding 的 chunked 分帧与 Content-Encoding 压缩不同：无 Length 的正常 chunked 响应允许；连接关闭定界的有限响应也允许。正式响应有 Length 时按第 6.3 节核对，不修改现有正大小路径的请求库解析规则。
- 不新增 HEAD 回退，不把 204 当空文件成功，不放行 `416 + Content-Range: bytes */0`。部分真正空对象对探测 Range 返回 416，仍按原 4xx 拒绝；A 也仅覆盖成功 200 空响应。
- 当前有大小的 `200 text/html` 不会统一判成登录页。本次不新增 HTML、扩展名或内容猜测拦截；401/403 拒绝照旧。200 登录伪装的风险见第 9、11 节。

### 4.2 引擎内的入口边界

新能力资格必须为：**普通 `file` 任务、规范化后 `request_context is None`，且探测明确属于新增成功类别**。创建时普通类型由原函数保证，重探测 / 校验时再次核对任务类型。

不能根据“有无 Cookie”或上下文字典真假判断。`normalize_context` 即使面对空请求头，也返回带 `url/headers/media` 的字典。所有带浏览器上下文的任务均保持旧限制，含可能的浏览器媒体普通文件分支。

探测和建任务均设置边界，启动重探测执行同一规则：

1. 右键未知 / 空文件继续失败，不建任务、不预留路径、不发成功回执。
2. 右键原先成功的有大小任务，后续重探测变成无 Length / 零大小时仍启动失败，不进入新模式。
3. 视频继续由原 VIDEO_KINDS 路由处理，不经新能力。
4. 不增加来源协议字段、桥接 feature 或扩展权限，不修改 BrowserBridge。

这是满足“入口源码与行为均不变”的必要设计，不能只列测试、等失败后再决定是否隔离。

## 6. ChunkDownloader：显式未知大小模式

### 6.1 分支隔离

仅在构造函数末尾新增带默认值的内部关键字参数，例如 `unknown_size=False`、`accept_empty_response=False`。后者仅在新模式使用，A 传 True、B 传 False；无 Length 的正常空流不受后者限制。

只有 `_start_singlethread_download` 为第 5 节的新任务显式开启模式。不依据 `end_byte=-1`、`total_size is None` 等模糊状态自动推断，避免影响旧调用。开启时必须满足 `use_range=False`、`start_byte=0`、`total_size=0`、`end_byte=-1`；错误组合拒绝，不能退回可疑分块路径。

| 模式 | 预期长度 | 完成条件 | 临时字节复用 |
|---|---|---|---|
| Range，单线程 / 多线程 | `end-start+1` | 原严格状态、范围和大小检查 | 原身份核对 + Range 续传 |
| 非 Range，有大小 | `end-start+1` | 原上限及最终大小相等 | 原同响应暂停；重建请求从零 |
| **非 Range，未知 / 待确认空大小** | 内部 `expected_size=None` | 正式响应正常 EOF，并满足第 6.3 节 | 同响应可暂停恢复；重试 / 重建从零 |

Range 不允许 `expected_size=None`，不能共用“EOF 即完成”。两个旧分支内的长度、Content-Range、身份和状态码检查保持原样。

### 6.2 `download` 的新分支

保留目录创建、错误槽、节流回调、暂停取消、重试次数和退避调用。未知模式明确隔离三处固定大小逻辑：

1. 不按 `downloaded_bytes > expected_size` 判断超长，不与 None 比大小；原非 Range 重建 / 重试清空临时文件的规则继续执行。
2. 不允许 `downloaded_bytes == expected_size` 的本地快捷成功。有空文件、非空残片或相同 ETag，都必须真实发起本次请求。
3. 只有 `_download_chunk` 正常返回 True 才成功。暂停取消返回 False；异常不转成 EOF 成功。

每次重试按非 Range 规则截断为零再请求，不发送偏移、不 append 之前响应的数据。同一工作对象的内存暂停不重入这个重建流程，保持旧语义。

### 6.3 `_download_chunk` 与完成判定

共同前置判断保持：正式请求期望 200，沿用原身份条件头、ETag / Last-Modified 比对、编码拒绝、超时、代理与暂停取消检查。

新分支依次执行：

1. 以 `wb` 开始本次完整响应，**先创建真实临时文件**，不因可能为空而省略打开文件。
2. 仍用 `iter_content(chunk_size=8192)`，逐块调用原共享限速器、写盘、上报；不把整个响应装入内存。迭代空块只跳过，不是 EOF。
3. 不按探测哨兵 0 截断，也不套用 Range 的 Content-Range 完成条件。
4. 正式 GET 仍无 Length 时，仅迭代正常结束且未暂停、取消或异常才成功。chunked 缺结束块、断流异常、超时都失败 / 重试；不能在 finally 中标成功。
5. 正式 GET 改为合法正 Length 时，按**本次响应长度**核对实际读取量，不能因探测未知就允许短文件。探测和正式响应无需保持相同长度头形式。
6. 正式 GET 明确 Length=0 按 A / B 执行；A 也必须真实请求、正常结束。B 在此以 fatal 拒绝，不重试、不落成品。无 Length 而正常 EOF 得到 0 字节，两案都可成功。
7. 新分支遇到非法 / 负 Length 或冲突分帧信息，按 protocol 拒绝；不能忽略头包装成功。这些新检查不插入原正大小分支。
8. 成功前强制上报最终实际字节数；保留 `download()` 布尔返回及既有失败分类，不新增任务状态。

下载阶段仍用总大小 0 上报；正式响应后来带正 Length 也无需中途改变 UI 或数据库模式，EOF 时统一落库真实大小。长度检查以 requests 提供的 HTTP 响应分帧为边界，不承诺检测服务端在有效响应之后发送的额外协议外数据。

## 7. EOF、校验与非覆盖发布

`_start_singlethread_download.download_and_finish` 通过原 run_id、暂停和取消保护后，仅为新模式成功结果向 `_verify_and_finish` 传明确的 EOF 证明，例如新增默认 False 的内部关键字 `eof_confirmed`。

不能在共享校验函数简单写“total<=0 就跳过”：视频完成、分块合并也调用它，默认路径必须保留旧行为。新分支同时要求：

- 本次工作对象正常 EOF 成功；
- 普通 file，无浏览器上下文、非 Range、单线程，且本次下载开始时为零大小哨兵；
- 原 `_can_finish(task_id, run_id)` 仍通过。

接着执行：

1. 从实际临时文件读取 `actual_size`，异常仍失败；新分支不拿它与哨兵 0 比，旧已知大小分支仍严格比对。
2. 用现有 `db.update_task_size(task_id, actual_size)` 回填总大小；后续读取更新后的任务，不能带着旧 task 字典的 0 继续计算。
3. 保留当前顺序：进入 verifying，计算哈希，执行原位置的 `publish_download`，再比对预期 MD5/SHA256 或记录校验结果，最后 `_finish_task`。**不改变原先后次序**；当前哈希不匹配也可能已发布文件并标记 verify_failed，本功能不顺带改成“仅匹配后发布”。
4. `_finish_task` 一行不动，由已落库实际大小正确回填进度、历史和平均速度。非空成品通过现有回调显示 100%。
5. 空文件保留实际大小 0，计算正常空内容哈希；不匹配仍 verify_failed。不能以 1 字节占位伪造 100% 或绕过哈希。

`eof_confirmed=False` 的全部旧调用保持原大小检查。最终发布仍使用同卷非覆盖改名、跨卷排他临时复制再改名；不改覆盖式 replace，不删除其他用户文件。

## 8. 启动重探测、资源身份与恢复

`_prepare_file_task` 保留旧正大小分支，仅对新增成功类别且符合入口资格的任务允许 size=0。压缩、HTTP 错误、失败探测和浏览器零大小仍失败。

### 8.1 重建请求与同响应恢复

- 大小仍未知时，身份按原优先级判断：旧强 ETag 优先，否则看可信 Last-Modified；弱 ETag 不可信。不能把 `0==0` 当资源身份相同的证明。
- 身份相同也不能复用非 Range 残片。新的完整请求必须 `can_resume=False`、从零写入；验证器不赋予 Range 能力。
- 活跃非 Range 对象的内存暂停恢复仍走原 `resume_download`，不重探测；同一响应继续读取不是跨请求续传。
- 失败重试、程序重启、取消后重新开始均重新 GET。残片可按原规则保留用于状态展示，但下次写入前清空，不能作为完整文件发布。
- 复用 `update_task_resource` 原事务更新大小、验证器和分块 / 进度。模式变化不得留下旧分块，无需数据库迁移。

### 8.2 探测状态转换

| 旧任务 / 重探测结果 | 行为 |
|---|---|
| 正大小 → 同正大小、Range / 验证器不变 | 原分支原行为，保留原断点判定 |
| 正大小 → 新成功的未知大小，自身入口 | 重置旧块和进度，进入新模式，不拼接旧内容 |
| 未知 → 仍未知 | 非 Range 单线程，新请求从零；不因零哨兵比较快捷成功 |
| 未知 → 正大小 | 更新元数据，再执行原 Range / 验证器门槛；未知流残片不能升级为 Range 断点 |
| 未知 → 显式零长度 | A 继续真实空响应流程；B 拒绝 |
| 浏览器正大小 → 未知 / 零大小 | 保持原启动失败，不进入新模式 |
| 任意 → HTTP 错误 / 超时 / 压缩 / 非法协议 | 原失败，不误创建或完成 |

未知转正大小后若能分块，仍复用原分块构造、调度和每块身份校验。正大小任务之间的大小比对继续保留，不能把“未知身份只看验证器”扩散到全部续传任务。

## 9. UI、磁盘与完整性限制

**UI 不改的真实呈现**：下载中显示“已下载 X / 未知”，百分比 0.0%，ETA 为 --，速度和曲线继续更新；非空 EOF 后回填实际大小，最终显示 100%。空文件状态为“已完成”，磁盘和数据库大小为 0，但原格式化仍显示“0 B / 未知”、0.0%。这是零 UI 改动的明确边界，不宣称已有空文件专用完成视觉状态。

**磁盘预检**：正大小的需求 / 余量 / 同盘归并及合并前暂停原样。未知无法计算完整需求，不能假报已确认容量。写盘、跨卷发布耗尽空间时沿用现有异常和清理，不新增保证。新模式不走 `_merge_and_finish`，也不会获得分块合并前的空间预检。

**有限流与完整性**：正常 EOF 证明 HTTP 响应正常结束，不证明服务端生成业务完整文件。连接关闭定界时，服务端提前正常关闭可能无法检测；预期哈希存在时照常校验，否则无法提供额外完整性保证。持续有数据且不结束的流不会自行完成，保留原超时、暂停、取消，不扩展成直播录制。

**成功 HTML 的边界**：401/403 登录页继续拒绝；200 的登录页不能仅靠无 Length 判定真实性，本次不新增内容嗅探或站点特例。
