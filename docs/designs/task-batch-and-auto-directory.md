## 1. 改动量结论

两项合起来属于**小到中等改动**，能够沿用现有模块，不需要新增依赖、数据库列或下载传输路径。多选的主要工作在选择状态、异步编排和调度保护；分目录主要是在创建任务时决定最终保存目录。

| 功能 | 预估 | 可直接复用 | 必须处理的边界 |
|---|---|---|---|
| 多选批量操作 | 小到中 | 单任务操作、UI 事件队列、卡片筛选与排序 | 隐藏项不被误操作、排队任务暂停、Tk 不阻塞、并发限制与退出 |
| 自动分目录 | 小 | 六类文件分类、设置页、路径预留、空间检查、非覆盖保存 | 最终文件名判类、显式目录优先、浏览器默认目录、旧任务路径固定 |

预计触及 7 个运行源码文件：`main_window.py`、`task_manager.py`、`config.py`、`settings_dialog.py`、`file_utils.py`、`download_engine.py`、`browser/bridge.py`。另增加或调整有针对性的测试及 README；具体行数以实施结果为准。

不把本轮扩大为列表分页、侧栏滚动、定时下载、失效链接更新或跨任务重复链接检测。沿用现有字号、主题、侧栏 240px、菜单项与悬浮条。

## 3. 多选交互

### 3.1 选择与操作栏

每张卡片的文件名行左侧放小勾选框，文件名保留现有字号与双击详情行为。仅勾选框切换选择；卡片空白处、操作按钮及右键不改变选择，不增加 Ctrl/Shift 范围选择。

搜索行下方、任务列表上方增加固定高度的紧凑操作栏，建议单行：

```text
[全选当前列表] 已选 0  [暂停] [开始/继续] [重试] [删除记录] [清空]
```

复用现有 CTk 控件与主题。900×600、侧栏 240px 时必须放得下；单行不足可把选择与动作分两行，但布局高度固定，不随计数变化跳动。无选择时动作禁用，选择入口仍可用。首版不用全局快捷键或三态全选，避免占用搜索和 URL 编辑操作；勾选状态不能只靠颜色表达。

### 3.2 选择范围

- 主窗口维护内存集合 `_selected_task_ids`，不持久化，重启清空。
- 全选是当前分类、搜索、隐藏已完成交集中的全部任务，包含需要滚动才能看到的卡片。
- 筛选或状态变化后清除不匹配的选中 ID，切回不恢复，不能保留不可见选择。
- 新任务不自动选；删掉的 ID 及时清理。集合、计数与勾选框同步。
- 全选和清空只改选择，不联网、不改任务状态。
- 点击操作时按当前列表顺序复制 ID 快照。后台只处理快照，新增任务、筛选变化或自动隐藏不改变已提交范围。
- 完成后保留仍可见的选择，成功删记录的移除；汇总按提交时总数计算。

### 3.3 状态与动作

| 动作 | 执行时可处理状态 | 处理方式 | 其他状态 |
|---|---|---|---|
| 暂停 | downloading、pending | 调用 pause_task，保留断点 | 跳过 |
| 开始/继续 | pending、paused | 调用 start_task，并发满则正常入队 | 跳过，不暗中重试失败 |
| 重试 | failed、verify_failed、cancelled | 调用 start_task，保留校验失败重置逻辑 | 跳过，不重下已完成文件 |
| 删除记录 | 除 verifying 外的现有任务 | 一次确认后调用 delete_task | 校验中的跳过，提示稍后重试 |

按钮可依据缓存启用，执行前必须重新查库。任务不存在算跳过，方法返回 False 或异常算失败；一项失败后继续其余项。成功开始包括已进入 pending 等待槽位，不表示下载完成；所有开始/重试必须经过现有并发门禁。

### 3.4 删除记录

批量按钮及确认标题都写“删除记录”，只删任务与关联分块记录，**不额外删除成品或断点文件**；保留原取消流程对会话暂存副本、临时凭据的清理，剩余断点继续按原孤儿清扫规则处理。单任务原有“同时删除已下载的文件”保持原样，首版批量入口不提供此选项。

只确认一次，明确数量、少量文件名及“文件将保留”；取消不得调用删除或取消接口。确认后在后台等待所选线程释放，再删除记录，保留原取消/会话失效保护；不能先销毁 UI 再假定成功。

仅成功删除的任务在 Tk 主线程清理卡片、详情窗口和 `_speed_history`。提取现有单任务删除后的 UI 清理为小方法复用，同时移除选择；不改变单任务实际删除文件的流程。失败的记录和卡片保留。

## 4. 批量接口与调度约束

给 TaskManager 增加一个小接口，不为每个动作建立独立框架：

```python
batch_operate(task_ids, action) -> dict
# action: pause / start / retry / delete_records
```

固定返回 `action`、`total`、`succeeded`（ID 列表）、`skipped`、`failed`。后两项为 `{task_id, reason}` 列表；每个去重 ID 恰好落入一类，三类数量之和等于 total。原因用简短分类文案，不把 URL、Cookie、浏览器上下文或原始异常写入 UI/日志。

1. 校验动作，保序去重，按现有 list_order 的列表顺序执行，不按 created_at 重排，不用 set 丢顺序。缺失 ID 也须出现在 skipped。
2. 只允许一批新操作同时执行，二次提交明确返回忙碌；UI 点击时立即设忙，防止 worker 启动前重复点击。
3. UI 在后台调用接口，经现有 `_ui_events` 回 Tk。worker 不读 CTk 变量、不操作控件、不弹框；暂停/删除的线程等待不能阻塞 Tk。
4. 操作期间禁用再次提交、勾选及冲突的单任务/全局操作，finally 恢复。搜索和查看可继续，它们不改变后台快照。
5. 暂停/删除整批期间先暂缓自动出队，结束恢复并正常调度一次。否则暂停 A 后会先启动同批待暂停的 B。
6. **开始/重试不能套暂停调度门禁**，否则 start_task 会被自己全部拒绝。
7. 暂缓须与 pause_all、回调、shutdown 共存。建议给新批量暂停加独立计数式 hold，接入开始/继续/自动出队检查；不能 finally 一律把 `_scheduling_paused` 清 False，覆盖退出的 True。不得拿着 manager 锁等待会回调取同一把锁的下载线程。
8. 批量增加 activity generation 并计入 get_activity_state 的 busy；UI 提交到 worker 开始的间隙也须被 `_has_active_tasks` 识别，防止完成后关机抢跑。所有出口释放 busy/hold。
9. 关闭程序后停止提交及后续逐项启动，沿用现有暂停退出流程；迟到结果不能访问销毁的窗口，finally 不能重启退出后的调度。

结果用状态栏反馈，如“暂停：成功 3，跳过 1，失败 0”。失败时可额外显示一次简短汇总，不能逐项弹框或把入队报成下载完成。

## 5. 自动按类型保存目录

### 5.1 设置与分类

新增布尔配置 `auto_classify_downloads`，默认 **False**，旧配置由 DEFAULT_CONFIG 补齐。在设置“下载”标签的默认下载目录下增加“按文件类型自动建立子目录”，说明“仅影响新任务；手动指定保存位置时使用该位置”。

接齐 `_load_config`、`_on_save`、运行时回调和 `_on_reset`：保存失败回滚内存，恢复默认关闭，成功仍用状态栏提示。检查固定尺寸布局，必要时小幅增加设置窗高度或压缩目录区间距，不改全局字号或重构整页。

| 原分类键 | 默认根目录下的子目录 |
|---|---|
| video | 视频 |
| audio | 音频 |
| document | 文档 |
| archive | 压缩包 |
| program | 程序 |
| other | 其他 |

直接复用 `guess_file_category` 与 `FILE_CATEGORY_LABELS`。当前没有单独“图片”，jpg/png、未知扩展名及无后缀按原规则进入其他。本轮不加新分类、MIME 猜测、多级规则、自定义映射或事后移动。

### 5.2 公共路径函数

在 file_utils.py 新增纯函数，例如：

```python
resolve_download_directory(base_dir, filename, auto_classify=False) -> str
```

关闭时返回根目录，开启时拼接现有分类标签；不请求、不建目录、不查库、不移动。子目录名只来自固定表，不能用 URL、MIME 或未经校验的文件名片段拼目录。继续文件名校验，不绕过越界及 Windows 非法名称保护。

不新增路径分配器，最终完整路径交给原事务 reserve_path=True；启动前重查与 publish_download 的非覆盖语义不变。

### 5.3 普通文件接入顺序

1. 保留原输入校验和探测，不改未知大小/空文件及浏览器限制。
2. 最终有效文件名按显式名/CD/重定向地址/原地址确定后，再决定目录。
3. 指定非空保存目录就原样使用，**即使其文字与默认根目录相同，也不附加子目录**。
4. 未指定目录才读取默认根和配置，调用路径函数并拼接文件名。
5. 空间检查使用最终路径，事务预留、线程和分块创建保持原样。

URL 无后缀而 CD 为 report.pdf 时进入文档。单链接、多行添加、剪贴板和稍后下载走同一创建流程，分别分类。关闭时路径保持旧行为；不预建六个空目录。子目录沿用原发布/合并建目录逻辑，不可写按原失败流程反馈，不静默回退根目录。

### 5.4 浏览器及视频

不修改扩展、Native Messaging、消息字段或 feature，只调整桌面 bridge 的默认目录调用：

- 普通右键：download_file 不再把默认目录作为显式 save_path，传 None 或省略，让引擎在探测最终文件名后分类；上下文及原拒绝规则保留。
- 视频：dispatch 取得已校验 video_filename 后，用公共函数算目录，再在**这个目录**做原重名预选。将已解析目录原样传给 add_youtube_task 或 mp4 文件分支，不二次附加视频目录。
- create_youtube_task 支持 directory=None 表示默认分类目录；已有显式目录原样使用，不改参数顺序、清晰度、下载类型、Cookie/分轨或平台校验。
- 最终仍用数据库事务预留；视频成功回执从实际落库任务取 filename，避免并发重名后回执仍是预选旧名。

开启时浏览器新普通文件与视频同样分类，关闭时用原目录；不能顺带放开浏览器普通文件未知大小/空文件的拒绝。

### 5.5 旧任务与开关变化

任务落库后 save_path 固定。改开关或默认根只影响以后新建任务；旧的排队、暂停、失败、下载中、完成记录都不搬、不改路径。恢复和重试用已存路径，不重新分类造成视频/视频嵌套。

temp_dir 独立，不按类型分目录、不搬断点。空间检查、同卷改名/跨卷复制、目标同名不覆盖继续原实现。

## 7. 验收矩阵

使用项目既有 py310_env 和隔离配置/数据库/临时目录，不能操作真实 data、dist/data 或用户文件。本轮文档阶段以下均**未执行**。

### 7.1 多选与批量

| 编号 | 必须证明的行为 |
|---|---|
| B01 | 初始无选择；勾选、清空、全选只改选择，不触发双击详情或下载 |
| B02 | 分类/搜索/隐藏交集全选，不选未匹配任务；滚动视口外但匹配的仍可选 |

| B13 | UI 提交与 worker 开始间隙及整批处理中不触发完成后关机；generation 使旧倒计时失效 |
