# v0.10.0：未知大小与零字节普通文件下载

发布日期：2026-10-21。桌面版 v0.10.0，浏览器扩展 0.6.2（未改动）。

以前，在下载器内添加链接时，如果服务器没有提供文件大小，或明确返回零字节，任务会被拒绝。本版支持这两类成功的 HTTP 200 普通文件响应，通过现有单线程流程下载，正常结束后记录实际大小并执行原哈希校验。

## 新增能力

- **未知大小文件**：没有 Content-Length 的有限响应，以及正常 chunked 响应，可以直接在下载器内添加、下载。
- **零字节文件**：成功的 `200 + Content-Length: 0`，或无 Length 且正常结束的空响应，生成真实空文件，正常计算 MD5 / SHA256。
- **真实结果回填**：下载期间显示“已下载 X / 未知”；正常 EOF 后更新任务总大小、最终进度和历史记录，非空文件显示 100%。
- **失败重试**：可识别断流、缺失 chunked 结束块或超时仍按原规则失败 / 重试。重试从零写入，不能把上一次响应残片拼入新文件。

## 原有行为保持

- 浏览器右键普通链接仍拒绝未知大小和零字节文件；本次新能力仅供下载器自身的普通文件入口。插件、Native 协议、BrowserBridge 源码和扩展版本均未修改；桌面双 EXE 按正式发布流程整体重建。
- 有大小的非 Range 单线程、Range 单线程、多线程分块、身份核对和分块失败重试保持原规则。
- 新任务复用现有普通文件共享限速器；总限速语义不变，视频仍按单任务限速。
- 同名不覆盖、路径预留、同卷改名和跨卷暂存复制保持原样；原配置、数据库、记录和断点无需迁移。
- UI、任务调度、数据库结构、代理和完成后动作均未修改。

## 完整性与兼容边界

- 压缩流、401/403 登录页、其他 4xx/5xx、非法长度或分帧信息仍拒绝。未知模式正式响应同时包含 chunked 与 Content-Length 时拒绝。
- 204、416（含空对象的 `bytes */0`）不扩展支持；本版零字节能力限于成功的 200 响应。
- 同一个活跃非 Range 响应仍可暂停 / 继续；重启、失败重试或重新请求时从零下载，不提供服务器未支持的跨请求续传。
- 无 Length 的正常 EOF 只证明 HTTP 响应正常结束，不能证明服务端业务内容完整；有预期哈希时继续校验。持续不结束的流不属于本版有限文件支持范围。
- 未知大小无法预估完整磁盘需求；原有已知大小空间预检不变，实际写盘或发布失败不会误报完成。
- 空文件状态正确标为“已完成”，实际大小为 0；由于 UI 保持原样，进度仍显示 0.0%，总大小占位仍为“未知”。
