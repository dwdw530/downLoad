# v0.7.2：修复小红书网页视频无法下载（真实页面结构适配）

发布日期：2026-10-18。桌面版 v0.7.2，浏览器扩展 0.6.2。

## 修复的问题

v0.7.1 的小红书适配在真实登录态页面上**一条视频都下载不了**，面板显示「未获取笔记视频信息」。用户实测反馈后逐层取页面真实数据定位，确认页面数据本身正常，是适配代码认字段的方式已过时。以下四项任意一项单独存在都会让流程直接返回“没有可用视频信息”：

| 项目 | 真实页面（实测） | v0.7.1 的假设 |
|---|---|---|
| 档位键名 | `video.media.stream` 的键是 `EF4`/`EF5`/`EF6`/`EF7` | 只读 `h264`/`h265` |
| 编码字段 | `videoCodec` 的值就是档位名（如 `EF4`） | 必须等于 `h264`/`h265` |
| 地址协议 | `http://sns-video-v3.xhscdn.com/...` | 强制 `https:` |
| 分辨率方向 | 720×1280、1080×1920、1440×2560（竖屏） | 按 `height <= 上限` 判断 |

另外两条兜底同样不可用：`EF5` 是 `.m4s` 分片（本就不该当完整文件），页面 `<video>` 使用 `blob:` 地址，因此“退一步读播放器”的路径也走不通。

## 本次改动

- 页面解析不再依赖档位键名，按位置遍历 `media.stream` 下所有档位；只排除明确的 `av1/av01/h266/vvc`，`h265/hevc` 记为 h265，其余（含 `EF*`）按 h264 处理。
- 只接受路径以 `.mp4` 结尾的完整文件，`.m4s` 分片自动排除。
- `http://` 仅把协议替换为 `https://`，路径与签名参数保持不变（`sns-video-v3.xhscdn.com` 的 https 已实测可用）。
- 清晰度档位统一按**短边** `min(宽, 高)` 判定：1080×1920 视为 1080p，720×1280 视为 720p，不再因竖屏被上限过滤掉。
- 删除基于 `streamType` 数字猜测水印流的规则（真实页面是 259/261/3041-3043，与早期资料不符）。
- 桌面端不再使用 yt-dlp 的 `[height<=N]` 选择器（竖屏下恒为 `Requested format is not available`），改为按短边校验后固定 `--format <format_id>` 下载那一条；仍保留 `--load-info-json`、ffprobe 音视频轨与时长校验。
- 补上小红书兜底分支漏掉的 `await`，以及读取 Cookie/设置前缺失的第二次复核。
- `dist/chrome-extension/` 与源码逐字节同步（v0.7.1 期间 dist 落后于源码，浏览器实际加载的是旧脚本）。

## 兼容与边界

- 不支持的仍不支持：图文笔记、LivePhoto、`xhslink.com` 短链、无水印原画、合集批量、直播。
- 仅当笔记详情页能定位到当前笔记、且存在不高于所选清晰度（按短边）的 `.mp4` 稳定流时才下载；不猜测地址。
- `xsec_token` 等来源签名参数只留在浏览器内，不写入数据库、日志或任务 URL。
- YouTube / X / B 站 / 抖音 / HLS / DASH / 右键普通链接下载、剪贴板、队列与界面行为未改动；共享分类器与安全模型零改动。

## 下载与升级

- 安装版：`daw-downloader-v0.7.2-windows-x64-setup.exe`，可选择安装路径并从系统卸载。
- 便携版：`daw-downloader-v0.7.2-windows-x64.zip`。
- 独立扩展：`daw-browser-extension-v0.6.2.zip`。
- 校验：安装包附 `.exe.sha256`，ZIP 的 SHA256 见 `SHA256SUMS.txt`。

必须同时更新桌面程序（含 BrowserBridge）和扩展：先装桌面端完整包，再在扩展管理页重新加载扩展，并对已打开的小红书笔记页做**完整刷新**（F5）。只更新其中一边会提示「小红书模块尚未就绪」或继续使用旧解析逻辑。
