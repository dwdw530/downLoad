# IDM 界面借鉴四项改进（方案与实施记录）

日期：2026-10-10
范围：`downloader/`（UI + 少量核心参数透传），不涉及浏览器扩展、桥接与打包产物。

## 1. 背景与选定项

在 IDM 界面借鉴清单中选定四项：

| 项 | 内容 |
|----|------|
| 1 | 任务卡片显示「已下载/总大小」与「剩余时间」 |
| 2 | 批量添加：多行 URL，一行一个 |
| 3 | 添加对话框可选「开始下载 / 稍后下载（加入队列）」 |
| 5 | 任务列表搜索过滤 + 「隐藏已完成」 |

未选：速度曲线图(6)、悬浮迷你窗(7)、左侧分类树(8)、任务分组队列(9)。明确不做：不改分块/断点/调度引擎逻辑，不加新依赖，不动 `dist/`。

## 2. 方案要点

### 2.1 卡片信息（项 1）

- 卡片信息拆成两行（原来进度条/百分比/速度/状态挤一行，宽度已接近窗口上限）：
  - 行 1：进度条（`fill=x, expand`）+ 百分比 + 右侧「文件位置」
  - 行 2：`已下载 X / Y`、`剩余 mm:ss`、速度、状态
- 新增 `file_utils.format_remaining(remaining_bytes, speed)`：`remaining<=0` 或 `speed<=0` 返回 `--`；<1 小时 `mm:ss`，<24 小时 `h:mm:ss`，更大 `超过 1 天`。
- 只有 `downloading` 状态显示剩余时间，其余（含重启后回填、暂停、完成）一律 `--`；`total_size<=0` 时大小显示 `X / 未知`。
- 标签宽度写死，避免数字变化时整行抖动。

### 2.2 批量添加（项 2）

- `AddTaskDialog` 的「下载链接」由单行 `CTkEntry` 换成 4 行 `CTkTextbox`；解析规则：按行拆分 → 去空白行 → 去首尾空格 → 同批内按 URL 去重。
- 行数 >1 时自动禁用「文件校验」控件并显示灰字提示；回到 1 行恢复可用（单任务习惯不变）。
- 提交按钮：`开始下载`（Enter / Ctrl+Enter）、`稍后下载`、`取消`（Esc）。多行框内回车是换行，不加 `break`；`Ctrl+Enter` 提交。
- 1 条链接：沿用原同步流程与提示（保证既有行为与测试不变）。
- >1 条：后台线程逐条 `add_task`（每条都要发探测请求，同步会卡界面），完成后经 `_ui_events` 回主线程弹一个汇总框：成功数、跳过重复数、失败数（最多列 3 条原因）。日志只记数量，不记链接。

### 2.3 稍后下载（项 3）

- 关键点：`add_task` 建完就调 `_try_start_next_task()`，pending 会被队列立刻捡起，「稍后」必须一开始就不是 pending。
- 实现：`db_manager.create_task_with_chunks` 新增 `status='pending'` 参数参与 INSERT；`engine.create_download_task` 新增 `start_later=False` 并映射为 `paused`；`task_manager.add_task` 新增 `start_later=False`，为 True 时不触发队列调度。
- 复用 `paused` 状态，不改状态机、不加新状态；卡片自动显示「已暂停 / ▶ 继续」。不区分「用户暂停」与「排队等候」。

### 2.4 搜索过滤 + 隐藏已完成（项 5）

- 任务列表上方新增：搜索框（文件名/URL 子串、不区分大小写）+ 「隐藏已完成」勾选框 + 右侧 `显示 N / M` 提示。
- 统一入口 `_apply_task_filter()`：命中 `pack`、不命中 `pack_forget`（仅当 `winfo_manager()` 为空时重新 pack，避免打乱顺序）。
- 触发点：搜索框 `KeyRelease`、勾选框切换、新增任务、状态变更、删除任务。
- 空态：过滤后 0 行显示「没有匹配的任务」，无过滤条件且无任务显示「暂无任务」。
- 「隐藏已完成」持久化到 `config.json` 的 `ui_hide_completed`（默认 false）；搜索词不持久化。
- 过滤按原始字符串匹配，不做 percent 解码（中文文件名命中原名即可），限制记录在 README。

## 4. 测试计划

1. `format_remaining`：0 速度、未知总数、<1h、<24h、>1 天、已下载=总数。
2. 卡片：进度更新后 size/eta 文案；切到 paused 后 ETA 为 `--`。
3. 批量：2 有效 + 1 无效 → 建 2 条、汇总文案正确；同批重复 URL 只建 1 条并计入跳过。
4. 对话框：多行时哈希控件 disabled，删回 1 行恢复；多行框内回车不提交。
5. 稍后下载：落库 `paused`、未触发队列调度、卡片按钮为「▶ 继续」；「开始下载」仍为 `pending` 并自动进队列。
6. 过滤：搜索命中/无命中空态；隐藏已完成即时生效；`ui_hide_completed` 持久化。
7. 回归：既有 GUI 测试全绿（单链接添加、删除、清空历史、设置保存、完成后动作）。

### 5.3 启动窗口居中（2026-10-10 追加）

需求：`MainWindow.__init__` 里把 `self.geometry("900x600")` 改成按屏幕居中，尺寸仍 900×600。

实现要点与踩坑：

- CustomTkinter 的 `_apply_geometry_scaling` 只对 `WxH` 乘窗口缩放，`+x+y` 原样交给 Tk，而 `+x+y` 最终按物理像素生效；因此偏移要用 `winfo_screenwidth()/height()` 乘一次 `ctk.ScalingTracker.get_window_scaling()` 换算（200% DPI 下否则会偏到左上）。
- 尺寸和位置必须写进**同一次** `geometry()` 调用：先 `geometry("900x600")` 再单独调用 `geometry("+x+y")` 移动，实测会被二次偏移（传入 700 实际落在 1500）。
- 验证方式：另起一个 DPI-aware 进程通过 `winfo_id()` 拿到 HWND，`GetAncestor(GA_ROOT)` + `GetWindowRect` 读物理坐标，并与 `GetSystemMetrics` 的物理屏幕对比；同时用 `ImageGrab(all_screens=True)` 截图目视确认。实测外框落在 (700,400)、1826×1271，中心 (1613,1035) 对屏幕中心 (1600,1000) 偏差 (+13,+35)（DPI 缩放与边框误差），视觉居中。

### 6.1 本轮顺带修掉的一处遗漏

启动时任务列表为空时 `_apply_task_filter()` 不会被调用，右上角「显示 N / M」保持空白。已在 `_load_existing_tasks()` 末尾补一次调用，并**重新打包 + 复验**（否则源码与 dist 不一致）。首次构建后发现的这个问题，说明打包前应先看一眼空列表状态的真实截图。
