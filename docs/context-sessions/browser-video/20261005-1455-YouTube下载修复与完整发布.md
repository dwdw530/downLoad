### 历史：抖音推荐流直接下载（2026-10-12）

#### 目标与用户要求

- 用户在 `douyin.com/?recommend=1` 全屏推荐流里看到视频就要能**直接下载**，不接受「先点进详情页」或「先把它最大化」这一步；此前 2026-10-08 记录的「用户接受抖音在推荐页要求打开详情页」在本轮被用户明确取代。详情页与 `?modal_id=` 路径仍照旧可用，只是不能再是唯一手段。
- 改动只针对抖音：X、YouTube、B 站、HLS/DASH 与桌面校验规则都不动。

#### 已完成（源码与 dist 已同步，未提交 Git）

- **URL 识别放宽**（`chrome-extension/media.js` 的 `douyinUrl` + `content.js` `videoPostFor` 内同一份 `valid()`）：接受 `/video/<id>`，也接受**任意路径上的单个 `modal_id`**（含 `/jingxuan?modal_id=…`）；重复或非法 `modal_id` 仍拒绝。现场已生效：`douyin.com/jingxuan?modal_id=7695009790300294409` 的面板能列出「抖音-7695009790300294409 · 最高 1080p · MP4 音视频」。
- **推荐流兜底**（`content.js`）：新增 `replayDetail(id)` 重放页面已发出的同源 detail 请求，`douyinFeedPost(video)` 按播放器时长（±1s）+ 分辨率从最近 6 条 detail 里挑候选，`resolvePost()` 供 `open()` 与两处复核使用。**实测失败**：推荐流不为在播视频发 detail 请求，兜底拿不到候选，仍显示「未确认当前视频，请打开该视频的详情页后重试」。
- 当前是**临时诊断版**：`background.js` 用 `onBeforeRequest` 把抖音 `/aweme/` 请求记进 `chrome.storage.session` 的 `api:<tabId>`，`list` 回包多一个 `diagnostic` 字段；`content.js` 把它作为面板里的独立一行显示。源码与 `dist/chrome-extension/` 都是这一版，扩展版本号未动（仍 0.5.0）。

#### 已排除的推荐流识别路线（都有现场证据）

1. **URL**：`?recommend=1` 里没有视频信息，滑动换视频时 URL 不变。
2. **播放器附近的 DOM**：实测 3 个 `<video>` 上溯 6 层都没有 `/video/<id>` 或 `modal_id` 链接（feed 卡片整块靠 JS 点击）。
3. **页面自发的 detail 请求**：整个页会话只记录到 1 条，且属于另一条 45:41 视频（当时在播 10:57）；之前那条 `origin_type=quick_player` 的 detail 其实来自用户点开的快速播放器，不是推荐流。
4. **blob/MSE 直链**：`src` 与 `currentSrc` 都是 `blob:`，页面内拿不到完整 mp4 地址；`douyinvod` 分片在页面 performance 里也看不到（播放器在 Worker 里拉流），只有 `chrome.webRequest` 能抓到。

#### 扩展实际能拿到的数据（现场证据）

- 扩展 Service Worker 里读到 19 条去重后的 `douyinvod` 地址，**同一个 `fid`**：包含 `media-video`（br 505/325/316/228/219/217/120/114）与 `media-audio`（br 189/44/39）分轨，另有**一条无轨标记、br=826（最高码率）**的候选。该形态与详情接口里 `format: "mp4"` 的完整音视频地址一致，即「播放中的视频，完整文件地址其实抓到了」。
- 缺的不是媒体地址，而是**「这条地址属于哪个 aweme_id」**——拿不到 id 就没有可信的归属。

#### 关键约束（决定方案）

- 桌面端抖音路径（`downloader/core/youtube_downloader.py` 的 `video_request_context`）要求 `video.id` 等于 URL 里的 id、时长有限、格式必须是 `https://*.douyinvod.com` 且不含 `/media-video-/`、`/media-audio-/`；下载完成后 ffprobe 校验音视频轨与完整时长（偏差 > max(2s, 2%) 不发布）。
- 若改把抓到的高码率地址当 `kind=mp4` 直链发出去：`background.js` 会走普通文件下载任务（`TaskManager.add_task`），**没有 ffprobe 校验**，分轨文件会被当成完整视频发布，违反本项目 fail-closed 口径，不能作为方案。
- 结论：推荐流要落地，必须先拿到「当前在播视频的 id」这一现场证据，不能按「最新的地址大概就是它的」来猜。

### 本轮改动与验证边界

- 根因：原版能识别 HLS/DASH，但按钮、桥接和任务类型限制将其禁用；不能把“隐私模式访问”直接归因为需要登录。无痕扩展仍需浏览器手动授权，完整无痕下载链路未验证。
