# daw下载器 (PyDownloader)

一个类似IDM的多线程下载器，支持断点续传、队列管理等功能。

> **仅支持 64 位 Windows。** 程序依赖 Windows 的 DPAPI 加密、Chrome 原生消息注册表和 NSIS 安装包，代码中没有跨平台分支；在 Linux/macOS 上需要自行改造才能运行。

正式入口：`dist/daw下载器.exe`（原名“老王下载器”）。窗口、托盘和 EXE 使用统一的绿色下载箭头图标。旧配置和下载目录保持原样；浏览器扩展更新后需重新加载，原桥接标识不变。

Windows 用户可直接下载 [安装包 EXE](https://github.com/dwdw530/downLoad/releases/download/v0.10.0/daw-downloader-v0.10.0-windows-x64-setup.exe)，安装时选择目录，之后可从系统中卸载。[GitHub Releases](https://github.com/dwdw530/downLoad/releases/latest) 同时提供完整便携版 ZIP 和独立浏览器扩展；GitHub 自动生成的 Source code 是源码。

当前桌面版 **v0.10.0**、浏览器扩展 **0.6.2**（未改动）。本版新增**未知大小与零字节普通文件下载**：在下载器内添加的成功 HTTP 200 响应，即使没有 Content-Length 或明确为 0，也可通过现有单线程流程下载；正常流结束后回填真实大小并执行原哈希校验。浏览器右键下载仍保持原限制，多线程、续传、总限速及界面保持原样。[下载插件 ZIP](https://github.com/dwdw530/downLoad/releases/download/v0.10.0/daw-browser-extension-v0.6.2.zip) · [更新日志与升级步骤](docs/releases/v0.10.0.md)。升级桌面端后重启下载器即可，无需重新加载扩展。

项目现支持生成中文 Windows 安装包：安装时可选择目录、创建快捷方式，之后可从系统“已安装的应用”中卸载。双击 `build_installer.bat` 构建，产物在 `dist/*-setup.exe`；卸载保留配置、下载记录、断点和下载文件。完整步骤见 [安装包说明](docs/INSTALLER.md)。

## 功能特性

✅ **多线程分块下载** - 最多16线程，充分利用带宽
✅ **断点续传** - 支持暂停恢复；普通文件续传前校验远端版本，变化或无法确认时安全重下
✅ **未知大小与空文件** - 下载器内添加的无大小 / 零字节普通文件可单线程下载，完成后记录真实大小与哈希
✅ **失败分块单独重试** - 5xx/断流按退避重试失败的那几块，已完成的分块不重下；403/404 立即失败并保留已完成数据
✅ **队列管理** - 支持同时下载多个任务
✅ **实时进度显示** - 进度条、速度、状态一目了然
✅ **数据持久化** - SQLite存储，任务重启不丢失
✅ **批量添加** - 多行粘贴链接，一行一个，自动去重
✅ **任务筛选** - 按文件名/链接搜索，可隐藏已完成任务
✅ **分类树** - 左侧按状态（下载中/等待/已完成/失败）、文件类型（视频/音频/文档/压缩包/程序/其他）和站点分组筛选，带数量统计
✅ **右键菜单与手动排序** - 任务右键可开始/暂停、打开文件或文件夹、复制链接、上移/置顶、删除
✅ **速度曲线** - 双击任务卡片弹出详情窗，实时查看最近 3 分钟的速度走势
✅ **桌面悬浮条** - 可拖动的置顶小窗，实时显示总速度、当前任务进度和一分钟速度曲线（默认关闭，设置里开启）
✅ **剪贴板监视** - 复制下载链接自动弹出提示（可开关、可忽略站点）
✅ **主题切换** - 深色 / 浅色 / 跟随系统，在设置里切换并持久化
✅ **完成后动作** - 可设置下载完成后打开文件、打开所在文件夹或全部完成后关机（默认关闭）
✅ **简洁GUI** - 基于CustomTkinter，现代化界面

## Chrome 视频下载助手

网页视频识别和播放器悬浮下载按钮支持 MP4、WebM 直链、HLS/DASH 播放列表，以及 YouTube、X、B 站、抖音和小红书普通视频。页面视频复用 yt-dlp + FFmpeg，可选最高 480p/720p/1080p。抖音推荐页按当前播放器识别并取得完整 MP4 信息，保留详情页路径，校验音视频轨和完整时长；不会把分离的音轨、视频轨当成完整视频。无法确认当前播放器时，先播放视频或完整刷新页面后重试。小红书视频笔记详情页同样通过页面状态取得官方签名 MP4 并校验音视频轨与完整时长；不支持图文笔记、LivePhoto 与短链。

2026-10-13：原 `dist/chrome-extension/` 已更新为 0.5.2，抖音推荐页可直接识别当前播放器，并通过播放接口取得实际可用的下载地址。用户实测推荐页下载及播放成功，成品为 1080p HEVC + AAC、246.410 秒；详情页和 `modal_id` 路径保留。源码、正式扩展及其他站点回归通过，详见 [插件 0.5.2 更新日志](docs/releases/extension-v0.5.2.md)。本次无需重打包 EXE。

安装需要完整发布目录，包括 `BrowserBridge.exe`、`chrome-extension/` 和 `video-tools/`，具体步骤、权限与限制见 [浏览器视频集成说明](docs/BROWSER_VIDEO.md)。本功能不自动接管 Chrome 的普通文件下载，也不读取 YouTube 账号 Cookie。更新后须完全退出并重启下载器，重新加载扩展及刷新视频页。

普通网页链接另有手动入口：对链接点击右键，选择“使用 daw 下载器下载此链接”，才会把该 HTTP/HTTPS 链接作为普通文件发送给下载器；普通点击、另存为和浏览器自带下载保持原样。该入口独立于“识别视频”开关，普通文件不进入视频列表。此能力随 **v0.7.0 + 扩展 0.6.0** 交付，需要同时更新双 EXE 与扩展；独立审查和验证范围见[链接下载测试报告](docs/BROWSER_LINK_TEST_REPORT.md)。

重新加载扩展后，对已经打开的 X、YouTube、B 站、抖音、小红书标签页分别按 **F5 / Ctrl+F5 完整刷新**。只在网站内切换视频或进入帖子详情，不会重新加载旧页面中的扩展脚本，可能导致悬浮按钮消失、工具栏资源列表为空。X 仍支持首页浏览时下载，无需逐条进入详情页。

## 使用说明

### 1. 添加下载任务
- 点击 **"➕ 添加任务"** 按钮
- **下载链接支持多行**：每行一个链接，空行忽略，同一批里重复链接只加一次
- 多条链接会批量添加（后台逐条探测，完成后弹一个汇总框：成功/失败/跳过数量）；单条链接保持即时提示
- 选择保存位置（可选，默认保存到 `downloads/` 目录）
- 文件校验（MD5/SHA256）只在单条链接时可用，批量添加时自动置灰
- 提交按钮二选一：**"开始下载"** 立即进入下载队列；**"稍后下载"** 只加入列表，等你手动点「▶ 继续」
- 多行输入框内回车是换行，提交用 **Ctrl+Enter**（其它控件下回车等同「开始下载」）

### 1.1 任务列表显示与筛选
- 每张任务卡显示：文件名、进度条与百分比、**已下载/总大小**、**剩余时间**、速度、状态
- 剩余时间只在下载中且速度大于 0 时显示，其它情况显示 `--`；总大小未知时显示 `X / 未知`
- 列表上方可按 **文件名或链接** 搜索（不区分大小写，不支持通配符）
- 勾选 **"隐藏已完成"** 后已完成任务不再显示，该选项会写入 `config.json` 的 `ui_hide_completed` 并在重启后保留；搜索词不保存
- **左侧分类树**分三组：状态、文件类型（按扩展名判定）、站点（按链接主机名自动生成，含子域名）。括号里是当前数量，选中项会与搜索、「隐藏已完成」叠加生效，并写入 `config.json` 的 `ui_active_category`
- **右键任务卡片**弹出菜单：开始/暂停、打开文件、打开所在文件夹、复制下载链接、上移、置顶、删除任务；不可用的项自动置灰
- **上移/置顶**会改写任务列表顺序（落库的 `list_order`），重启后保留；等待中的任务按该顺序依次出队
- **双击任务卡片**（文件名、进度条等空白区域）打开任务详情窗：状态、进度、已下载/总大小、剩余时间、当前/峰值/平均速度，以及最近约 3 分钟的实时速度曲线；曲线仅在程序运行期间记录，重启后清空

### 1.2 桌面悬浮条（可拖动）
- 在 **设置 → 其他 → 显示可拖动的速度悬浮条** 开启；默认关闭，开启状态与位置写入 `config.json`（`ui_float_bar_enabled` / `ui_float_bar_pos`）
- 悬浮条始终置顶，不进任务栏；显示总速度、当前任务百分比、已下载/剩余时间、文件名和最近一分钟的速度曲线
- 按住卡片任意位置拖动，松手后靠近屏幕边缘会自动吸附；位置按物理像素保存，多显示器与高 DPI 下重启仍能回到原处
- **双击** 悬浮条显示主窗口；**右键** 可暂停全部/继续全部/打开设置/隐藏悬浮条/退出程序
- 从右键菜单隐藏后，该开关同时置为关闭，下次启动不再自动弹出；想再显示到设置里重新勾选

### 1.3 剪贴板监视
- 复制单个 `http(s)://` 链接时自动弹出小提示窗，点 **"添加任务"** 进入标准添加框（链接已预填）
- 弹窗不抢键盘焦点；点 **"忽略此站点"** 把该域名写入忽略列表并持久化（含其子域名，`www.` 会自动归一）
- 同一次剪贴板内容只提示一次；多行文本、非 http(s) 链接不触发；主窗口最小化到托盘或有模态对话框打开时不弹，过后也不补弹
- 可在 **设置 → 剪贴板监视** 里关闭该功能或编辑忽略站点列表（`clipboard_monitor_enabled` / `clipboard_ignore_hosts`）

### 1.4 失败重试策略
分块下载失败时不再“全军覆没”，按失败原因分三类处理：

| 失败原因 | 处理方式 |
|----------|----------|
| 超时、连接中断、5xx、429 | 临时性失败：指数退避（1s/3s/10s）只重试失败的那几块，已完成的分块不重下；最多 3 轮，总时长上限 5 分钟 |
| 403 / 404 / 410 / 文件版本变化 | 致命失败：立即失败并给出原因，不浪费时间重试；已下载的分块和临时文件全部保留，点「继续」可接着跑 |
| 服务器不守 Range（返回 200、Content-Range 不符） | 协议不支持：自动降级为单线程，从零重下（这种源本来就没有可拼接的分块） |

- 重试期间任务卡状态显示 `下载中 · 正在重试 N 个分块（第 x 轮）`，数据恢复流动后自动收回到 `下载中`
- 单个分块每次下载内部的重试次数取自配置 `retry_times`（默认 3）；分块之间的轮次与总时长上限是固定常量

### 2. 管理任务
- **▶ 开始** - 启动下载
- **⏸ 暂停** - 暂停下载（支持断点续传）
- **✗ 取消** - 取消任务
- **🗑 删除** - 删除任务记录
- **文件位置** - 打开文件所在文件夹（已下载会定位到文件）

### 3. 批量操作
- **↻ 重试失败** - 一次重试所有失败任务（≥10 个先确认），断网或平台限流后不用逐个点
- **⏸ 暂停全部** - 暂停下载中及排队中的任务，阻止队列继续启动
- **▶ 继续全部** - 继续所有暂停的任务

### 4. 设置
点击 **"⚙ 设置"** 按钮可配置：
- 默认下载目录
- 默认线程数（1-16）
- 同时下载任务数（1-5）
- 请求超时时间
- 总速度上限（所有任务合计，0 表示不限速）
- HTTP/HTTPS代理地址
- 下载完成后动作：打开文件 / 打开所在文件夹 / 全部下载完成后关机（默认全部关闭，关机前弹 60 秒倒计时确认，关窗即取消）
- 主题：**深色** / **浅色** / **跟随系统**（默认深色），保存后立即生效并写入配置

### 5. 关闭程序
- 点击窗口右上角关闭会弹出 **退出确认**（居中显示、布局更紧凑）：可选择“最小化到任务栏（继续后台下载）”或“退出程序（停止所有下载）”
- 勾选“记住我的选择”后，会写入 `data/config.json` 的 `close_behavior`（ask|minimize|exit）

## 技术架构

### 核心技术栈
- **GUI框架**: CustomTkinter
- **HTTP库**: requests
- **并发方案**: concurrent.futures.ThreadPoolExecutor
- **数据存储**: SQLite3
- **Python版本**: 3.10+（推荐 `py310_env`）

### 核心功能实现

#### 多线程分块下载
1. 流式GET探测 `bytes=0-0`，获取文件大小（兼容不支持HEAD的站点）
2. 根据真实响应确认Range支持，分块下载时核对Content-Range和实际字节数
3. 计算分块（文件大小 / 线程数）
4. 创建线程池，并发下载各分块
5. 实时监控进度
6. 分块直接合并到目标目录的临时文件，核对大小并计算哈希后安全改名，不再额外复制一遍成品

#### 文件安全与磁盘占用（v0.6.1）
- 拒绝解码后的路径越界、Windows 设备名和非法文件名。手动、批量与浏览器任务统一分配未占用名称；启动前再次核对，最终保存也不覆盖已有文件。
- 同卷使用 Windows 的非覆盖式 `os.rename`，不重新读写整份数据；仅遇到跨卷错误才复制。跨卷先复制到目标目录的临时文件，完成后再改成正式名称。
- 普通单线程任务同卷保存时，数据峰值占用接近文件大小的 **1 倍**；多线程分块约 **2 倍**（分块 + 合并文件）。跨卷复制需要同时保留源与目标副本。以上不包含其他任务、既有文件和文件系统开销，不是硬盘空间上限保证。
- 正常暂停、取消或失败会清理本次未发布的合并/复制副本，保留续传所需源文件或分块。强制结束进程、断电或文件被外部占用时，仍可能留下临时文件；不会递归清理用户目录。
- 本轮修复、打包与验收记录见 [下载器修复进度](docs/context-sessions/20260911-2143-下载器修复验证与新版EXE交付.md)，完整更新日志见 [v0.6.1 发布说明](docs/releases/v0.6.1.md)。正式 `dist` 已重建，历史 v0.6.0 记录与附件保留。

#### 断点续传
- 每个分块的下载进度实时写入数据库
- 暂停时保存当前进度
- 继续时核对保存的强 `ETag` 或 `Last-Modified` 及总大小，确认未变才从已下载位置继续；请求同时携带条件头并校验响应范围
- 资源变化、旧任务没有版本记录，或站点不提供可靠版本标识时，不拼接旧断点；无版本标识的普通文件使用单线程完整下载

#### 任务队列管理
- 状态机：pending → downloading → verifying → completed / verify_failed；下载中可暂停为 paused 再继续，任意非完成状态可转为 cancelled 或 failed
- 支持并发控制（默认同时下载3个任务）
- 任务完成后自动启动队列中的下一个任务
- 出队及「继续全部」均按 `list_order`（未手动调整时等于创建时间升序），右键「上移/置顶」改写该字段；并发已满时手动重试进入等待队列

## 配置文件说明

配置和数据库位于程序目录下的 `data/`；从其他工作目录启动EXE也使用同一份数据。配置文件为 `data/config.json`：

```json
{
    "download_dir": "C:\\Users\\<用户名>\\Downloads\\daw下载器",
    "temp_dir": "temp",
    "thread_count": 8,
    "max_concurrent_downloads": 3,
    "retry_times": 3,
    "chunk_size": 1048576,
    "timeout": 30,
    "user_agent": "PyDownloader/1.0",
    "proxy": {
        "enabled": false,
        "http": "",
        "https": ""
    },
    "close_behavior": "ask",
    "speed_limit": 0,
    "ui_hide_completed": false,
    "ui_active_category": "all",
    "ui_appearance_mode": "dark",
    "clipboard_monitor_enabled": true,
    "clipboard_ignore_hosts": [],
    "after_download": {
        "open_file": false,
        "open_folder": false,
        "shutdown": false
    }
}
```

`close_behavior` 取值为 `ask`（每次询问）/ `minimize`（最小化到托盘）/ `exit`（直接退出）；`speed_limit` 单位为字节/秒，0 表示不限速，非 0 时是**所有普通文件任务合计**的上限（视频任务仍按单任务限速）。

`temp_dir` 为临时分块目录（默认程序目录下的 `temp/`），也可在“设置”里修改并选择目录：保存后立即生效，新任务直接写入新目录；没有断点数据的排队任务会同步改路径，已有下载字节的任务继续使用原临时目录，避免移动大文件或破坏断点。临时目录与下载目录在同一磁盘时，完成后的发布是改名（不复制）；跨磁盘时会多一次完整复制。

`after_download` 控制下载完成后的动作，三项默认均为 `false`（不做任何动作）；只有校验通过（`completed`）才触发，校验失败（`verify_failed`）不触发。开启 `shutdown` 时，若队列里还有下载中/等待/校验中的任务，会等最后一个完成再弹出 60 秒倒计时确认框，点“取消”或直接关闭窗口都不会关机。后台探测与批量添加也计入未完成工作；倒计时期间新增或重试任务、关闭关机设置会使旧倒计时失效，真正执行前再检查一次。

`ui_hide_completed` 控制任务列表是否隐藏已完成任务，由主界面勾选框直接读写。

`ui_active_category` 记录左侧分类树当前选中项（`all` / `status:xxx` / `type:xxx` / `host:xxx`），`ui_appearance_mode` 记录主题（`dark` / `light` / `system`），两者都由主界面或设置界面写入，重启后恢复。

`ui_float_bar_enabled` 控制桌面悬浮条开关（默认 `false`）；`ui_float_bar_pos` 记录悬浮条左上角的物理像素坐标 `[x, y]`，为空或越界时回退到主屏右下角。

`clipboard_monitor_enabled` 控制剪贴板监视开关（默认开启）；`clipboard_ignore_hosts` 为忽略站点域名列表，由设置界面或弹窗的「忽略此站点」写入，保存前会自动归一化（小写、去 `www.`、去重）。

## 日志与排障

程序日志默认写入 `logs/app.log`（相对程序目录，滚动保留 3 个 2 MB 文件）。安装版若装在不可写目录，会自动回退到 `%LOCALAPPDATA%\LaoWangDownloader\logs\app.log`；设置对话框中的下载失败、分块降级、哈希校验、配置读写等记录都在这里。

- 打包后的 EXE 没有控制台，排障一律看该文件；源码运行时会同时在终端输出。
- 需要更详细的内容（含异常堆栈）时，设置环境变量 `DAW_LOG_LEVEL=DEBUG` 再启动。
- 日志不写入标准输出（stdout 是浏览器桥接的原生消息协议通道），也不记录视频链接与 Cookie。

## 数据库结构

任务表还包含校验（`expected_hash` / `actual_hash` / `hash_verified`）、浏览器上下文（`browser_context`）、任务类型与视频清晰度（`download_type` / `video_height`）等列，完整字段与状态机见 [design.md](design.md) 的「数据模型」。

### download_tasks（任务表）
- task_id: 任务ID（UUID）
- url: 下载链接
- filename: 文件名
- save_path: 保存路径
- total_size: 文件总大小
- downloaded_size: 已下载大小
- status: 状态（pending/downloading/paused/completed/failed/cancelled）
- support_range: 是否支持断点续传
- thread_count: 线程数
- speed: 当前速度
- list_order: 列表顺序（手动上移/置顶后改写；等待中的任务按该顺序出队）

### download_chunks（分块表）
- chunk_id: 分块ID
- task_id: 关联任务ID
- chunk_index: 分块序号
- start_byte: 起始字节
- end_byte: 结束字节
- downloaded_bytes: 已下载字节数
- status: 状态
- temp_file: 临时文件路径

## 常见问题

### Q1: 程序启动报错 "No module named 'customtkinter'"
**A:** 请确保已激活py310_env环境并安装了依赖：
```bash
conda activate py310_env
pip install customtkinter
```

### Q2: 下载速度为什么不快？
**A:** 可能原因：
1. 服务器不支持Range请求（自动降级为单线程）
2. 网络带宽限制
3. 服务器限速
4. 可以尝试调整线程数（设置 → 下载线程数）

### Q3: 为什么有些文件不支持断点续传？
**A:** 服务器需要支持 HTTP Range，并提供强 ETag 或 Last-Modified 以确认资源版本。部分动态链接不支持续传；版本变化或无法确认时会安全重下，避免新旧文件拼接损坏。

### Q4: 任务列表太多了，怎么清理？
**A:** 可以手动删除已完成或失败的任务。数据库文件位于 `data/downloads.db`。
